# State of Space (учебный)

Учебная пересборка макета State of Space с нуля — независимый проект в
`~/state-of-space-study/`, не связанный с production-версией сайта. Стек и
рабочий процесс скопированы из `frontend-developer` (эталонная заготовка для
вёрстки по макетам Figma). Задача агента — превращать выбранный в Figma фрейм
в рабочий React-компонент, максимально близкий к макету.

## Стек

- Vite + React 19 + TypeScript
- Tailwind CSS v4 (подключён через `@tailwindcss/vite`, без `tailwind.config.js` — токены
  задаются в `src/index.css` через `@theme`)
- oxlint для линта (`npm run lint`), Prettier для форматирования (`npm run format`)

## Figma MCP

Подключение — `.mcp.json`, сервер `figma` на `http://127.0.0.1:3845/mcp` (Figma Desktop
Dev Mode MCP Server). Если Figma Desktop и Claude Code на разных машинах — поднять
реверс-туннель с машины с Figma (командой пользователь управляет сам, выполняется
на его локальной машине, не здесь):

```
autossh -M 0 -N -R 3845:127.0.0.1:3845 -p 2222 root@72.56.97.73 \
  -o "ServerAliveInterval 30" \
  -o "ServerAliveCountMax 3" \
  -o "ExitOnForwardFailure yes"
```

`autossh` сам переподключается при обрыве — предпочтительнее голого `ssh -R`,
который замертво виснет при разрыве сети/сна ноутбука. Если `autossh` не
установлен: `brew install autossh` (macOS) / `apt install autossh` (Linux).
Порт 2222, не 22 (ufw на сервере пропускает только 2222/80/443).

Перед работой с макетом: в Figma Desktop должен быть открыт файл и выделен нужный
фрейм/слой — MCP-инструменты (`get_code`, `get_image`, `get_variable_defs`,
`get_metadata`) читают именно текущее выделение.

## Договорённости по вёрстке

- Один компонент — один файл в `src/components/`, страницы — в `src/pages/`
  (внутри папки конкретного проекта, см. «Структура» и «Новый проект»).
- Цвета, отступы, типографику брать из переменных/токенов Figma (`get_variable_defs`),
  переносить их в `@theme` в `src/index.css`, а не прибивать значения руками в разметке.
- Изображения и иконки выгружать через `get_image`/экспорт из Figma, не через скриншоты
  вручную; складывать в `src/assets/`.
- Вёрстка — mobile-first, адаптив проверять на брейкпоинтах макета, если в Figma заданы
  несколько состояний/размеров фрейма.
- Семантичная разметка и доступность (alt, aria, правильные теги) — по умолчанию, не
  только когда попросили.
- Анимации задаются в макете через `anim`-токены в скобках в имени слоя
  (`Hero-title (anim: fade-up; delay: 100)`) — читать их и переносить в код, а не
  придумывать движение с нуля. Формат — `ANIMATION-TOKENS.md`, реализация —
  `src/lib/anim.tsx` + раздел «Анимации» в скилле `figma-to-code`.

## Анимации (anim-токены)

Дизайнер описывает анимацию элемента прямо в имени слоя Figma — коротким
структурированным токеном в скобках после имени/класса:

```
Feature-cards (anim: fade-up; stagger: 80; distance: 32)
```

Полный справочник по ключам и примеры — `ANIMATION-TOKENS.md` (эта же шпаргалка
отдаётся дизайнеру). Готовые примитивы под простые случаи (`fade`/`slide`/`scale`/
`blur-in`/`count` на триггерах `in-view` и `load`, `stagger`) — в `src/lib/anim.tsx`,
без внешних зависимостей. Для `trigger: scroll` / `anim: parallax` — `motion` по
факту; для настоящих пиновых скролл-сцен — Lenis + GSAP + ScrollTrigger. Паттерны
и грабли скролл-нарратива и переноса — разделы «Скролл-нарратив» и «CSS-ловушки»
в `.claude/skills/figma-to-code/SKILL.md`.

Отдельный случай — покадровые сцены: несколько фреймов подряд показывают один
экран в разные моменты скролла/анимации, а одинаковые имена слоёв между кадрами
означают один и тот же элемент в разных состояниях. Как их опознавать и
переносить в код (пин vs FLIP-переход между секциями, приведение px-координат
к флюидным единицам, desktop-only сцены) — раздел «Покадровые сцены» в
`.claude/skills/figma-to-code/SKILL.md`.

## Структура

Каждый проект — полностью самостоятельная папка рядом с `frontend-developer`
(например, `~/snapa/`), а не подпапка внутри него: свой `package.json`,
`vite.config.ts`, `git`-репозиторий и, при необходимости, отдельный
GitHub-репозиторий под GitHub Pages (см. «Новый проект»). Внутри проекта:

```
<project-name>/
  src/
    components/   переиспользуемые UI-компоненты
    pages/        сборка компонентов в страницы
    lib/          хелперы, хуки, утилиты
    assets/       изображения/иконки, выгруженные из Figma
  .claude/skills/ скиллы (скопированы из frontend-developer, см. figma-to-code)
  .mcp.json       подключение к Figma MCP (своё на проект)
```

## Новый проект

Когда пользователь говорит "создай новый проект":

1. Спросить название проекта, прежде чем создавать папку/файлы.
2. Создать папку `~/<project-name>/` (kebab-case) рядом с `frontend-developer`,
   как полностью самостоятельный проект — не подпапку внутри `frontend-developer`.
3. Скопировать туда базовый стек из `frontend-developer` (Vite + React + TS +
   Tailwind v4, `oxlint`/`prettier` конфиги, `.mcp.json`, `.claude/skills/figma-to-code`,
   `src/lib/anim.tsx`, `ANIMATION-TOKENS.md`, `CLAUDE.md` — адаптировать под
   конкретный проект, не копировать дословно) и поставить зависимости.
4. Инициализировать git (`git init`) в новой папке.
5. Спросить, нужно ли сразу создать и подключить удалённый GitHub-репозиторий
   (для GitHub Pages) — репозиторий у каждого проекта свой, отдельный от других
   проектов и от `frontend-developer`.

## Безопасность

- Токены и ключи (Figma PAT и т.п.) в репозиторий не класть, только в переменные
  окружения вне git.
- Перед необратимым действием (удаление файлов, force-push, публикация) — спросить
  подтверждение.
